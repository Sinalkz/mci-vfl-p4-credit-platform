# MCI loan instance v2 (MCI as the lender): how to reproduce every result and launch the dashboard

v2 is the second version of the MCI loan instance. MCI grants credit to its subscribers, so it is the active member: it owns the label, creates the federation and funds the pool. Its partners are the Bank, the E-commerce company and the Credit bureau.

v1 had the Bank as the active member. It is kept as it was: tag `mci-v1-bank-active`, `results/mci_loan/`, `docs/mci/`. v2 writes only under `results/mci_loan/v2/`, `docs/mci/v2/` and `data/mci_loan/v2/`; its code is in `scenarios/mci_loan/v2/`.

**The organisations are simulated.** Every partner is a generic simulated role over one public dataset, Kaggle Home Credit Default Risk. No real company's data is used, MCI's included (`docs/mci/v2/02-preregistration.md`, section 0). The thesis code keeps its slot names (`power`, `mci`, and two more); `scenarios/mci_loan/v2/slots.json` maps them to the user-facing names, and is the only place that does.

All commands run from the repository root, with the repository's `.venv` (Windows paths shown; on macOS or Linux use `.venv/bin/`). Each document names the results file behind each of its numbers.

## Step 3: the scenario and the pre-registration

```
.venv/Scripts/python -I scenarios/mci_loan/v2/select_mci.py            # MCI's 8 columns, the skip-no-effect rule (results/mci_loan/v2/select_mci.json), about 7 min
.venv/Scripts/python -I scenarios/mci_loan/v2/select_mci.py --literal  # v1's rule as it is, for the record (select_mci-literal.json)
.venv/Scripts/python -I scenarios/mci_loan/v2/prep2.py                 # data/mci_loan/v2/prepared/ and prepared-smoke/; checks the cohort and split against v1's
.venv/Scripts/python -I scenarios/mci_loan/v2/smoke2.py                # writes the configs (configs2.mjs) and runs the 1,000-row smoke check
.venv/Scripts/python -I scenarios/mci_loan/v2/prereg2.py               # docs/mci/v2/02-preregistration.md
.venv/Scripts/python -m pytest -q scenarios/mci_loan/v2/tests          # the party rule, the names, the calibration (no leakage), the tiers
```

The prepared binaries must match the SHA-256 values in `results/mci_loan/v2/prepared/manifest.json`; the loader checks them before every run. MCI's encoded columns are byte-identical to v1's Bank's, and every partner column equals its v1 counterpart.

## Step 4: the off-chain evaluation

```
node scenarios/mci_loan/v2/offchain/step4v2.mjs --set main     # per seed 1-10: C2, C4a-f32, C1b, the N = 64 draws
node scenarios/mci_loan/v2/offchain/step4v2.mjs --set scales   # LDP sigma x1, x0, x0.5, x4, seeds 1-10
node scenarios/mci_loan/v2/offchain/step4v2.mjs --set eps      # LDP epsilon 1, 4, 16, 64 per release, seeds 1-10
.venv/Scripts/python -I scenarios/mci_loan/v2/analysis2.py     # results/mci_loan/v2/offchain/*.csv, summary.json
.venv/Scripts/python -I scenarios/mci_loan/v2/results_doc2.py  # docs/mci/v2/03-results.md
```

The runs behave as v1's:
- **One process at a time.** A run whose output exists is skipped, so an interrupted set resumes.
- **The RAM floor.** No run starts with less than 2 GB free.
- **The commit check.** `meta-<set>.json` records the code commit and whether the tree was clean.
- **Determinism.** The same commit and data give the same figures and predictions (the check runs, `step4.log`).

The three sets take about an hour on the laptop.

## Step 5: the on-chain runs

These ran on the MacBook Air, in a checkout of this code (`mac-runs-v2.sh` takes the machine's tool locations from the environment, README.md): native Besu 26.8.1, rapidsnark, the thesis's maxDepth 14 multi-party key. Besu writes under its own WORK folder, `besu-native-mci2`. `data/mci_loan/v2/prepared/` is copied from the laptop; its SHA-256 values are checked.

```
bash scenarios/mci_loan/v2/onchain/mac-runs-v2.sh test                                   # thesis full-data tests and the loan tests
caffeinate -ims bash scenarios/mci_loan/v2/onchain/mac-runs-v2.sh bench                  # results/mci_loan/v2/onchain/psi-bench.json
.venv/Scripts/python -I scenarios/mci_loan/v2/onchain_plan2.py                           # plan.json, fixed before run 1 (any machine)
caffeinate -ims bash scenarios/mci_loan/v2/onchain/mac-runs-v2.sh run <k> <blocks>       # k = 1..5, blocks from plan.json (90)
bash scenarios/mci_loan/v2/onchain/mac-runs-v2.sh replay <k>                             # the six figures recomputed centrally
.venv/Scripts/python -I scenarios/mci_loan/v2/onchain_report2.py                         # check.json per run, CSVs, summary.json
```

The driver sets `MCI_LOAN_PREPARED` to the v2 folder, so every process reads v2's data. Process A (the `power` slot) is MCI: it creates the run and escrows the pool. The replay stops if its prepared data is not the run's.

## Step 6: the dashboard

```
.venv/Scripts/streamlit run dashboard/app.py                                    # http://localhost:8501 (bound to 127.0.0.1)
.venv/Scripts/streamlit run dashboard/app.py --server.address 0.0.0.0           # to show it on the local network
.venv/Scripts/python -I dashboard/export_figures.py                             # docs/mci/v2/figures/*.png, 300 dpi
.venv/Scripts/python -I dashboard/check_pages.py                                # every page headless, and the naming check; results/mci_loan/v2/dashboard-check.json
```

The dashboard reads only `results/mci_loan/v2/`. v1's dashboard (the Bank active) is at the tag `mci-v1-bank-active`. Its pages:
1. Consortium.
2. MCI alone and with partners.
3. Credit tiers.
4. What MCI pays each partner.
5. Settlement.
6. Audit trail.
7. Cost.
8. Privacy trade-off.

The banner on every page states that all partners are generic simulated roles over the public dataset (named: Kaggle Home Credit Default Risk) and that no real company's data is used. The page check fails if any rendered text names a real company other than MCI.

### The report figures

```
node dashboard/report_screens.mjs                                               # 4 page screenshots, 1,600 px wide (the dashboard and headless Edge, both stopped at the end)
.venv/Scripts/python -I dashboard/report_figures.py [--zip <path.zip>]          # the 17 charts and the policy flow, 16 cm at 300 dpi; captions.md; the zip
```

What the pack contains:
- **The charts** are the dashboard's, restyled for the report: no in-image title and no footer, since the caption carries both. Panels are stacked where 16 cm is too narrow for them side by side.
- **The font** is B Nazanin when installed, else Vazirmatn. ASCII comes from Times New Roman, as in Word, and the Persian separators from Vazirmatn. `report_figures.py`'s docstring explains why.
- **The dashboard's own figures** are not changed.
